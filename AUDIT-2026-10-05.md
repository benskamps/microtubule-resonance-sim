# Math audit, 2026-10-05

Every engine and hypothesis test was checked against first principles by the Flywheel math gate (`personal-infra/flywheel/adapters/microtubule/`), which now runs weekly against the published `main`. Each fix below has a gate check that fails on the old engine and passes on this one. Codex reviewed each round independently.

## Two verdicts changed

| Hypothesis | Before | After | Why |
|---|---|---|---|
| H2: Chirality creates triplets | Falsified | **Inconclusive** | Engine 4 dropped every n < 0 mode, which are the ±n pairs the helix splits. With all modes counted, the helix gives 16 triplet clusters at 12°, 6, 12. A matched null (100 random splittings of the same size) has a 95th percentile of 15, and the single-run verdict holds in only 2 of 9 nearby pitch and cutoff settings. The triplets come from splitting degeneracies in general, not from the helix. |
| H6: Noise as fuel (stochastic resonance) | Plausible | **Falsified (this parameter range)** | With a correct SNR estimate, SNR only falls as noise rises: 48 at D = 0.01, 0.005 at D = 4.01. There is no peak, which is the signature of stochastic resonance. The old "9× improvement" was an artifact. The old estimate counted the particle's offset in one well as noise, so quiet runs scored about 0.0002, and the curve seemed to rise. The verdict rule also accepted "max ≥ 3× the first point" with no peak required, and it computed `peakNotAtEdge` and never used it. Physically, the drive (relative frequency 0.7–1.4) is faster than the well's hopping rate can reach at any noise level tested, so there is nothing to resonate with. |

## Other fixes in this audit

- **SNR estimator (Engine 2).** It now uses a least-squares fit of offset + cos + sin on the samples: signal is the variance the fitted sinusoid explains, noise is the residual. The old `<x cos ωt>²` over `<x²>` counted the constant offset (a particle sitting in one well at x ≈ ±1) as noise. It was also half the in-phase power, ignored the quadrature part, and was wrong on partial windows. This is the change that flips H6.
- **Engine 2 drives.** The four "one per scale" modes were all the same 0.7 relative frequency. It now uses the three distinct ones (0.7, 1.0, 1.4).
- **H3.** It returned "consistent" when the triplet score was 0 at one end (ratio 0). It now reports inconclusive when the ratio is undefined. The verdict is unchanged, because the score is non-zero at both ends now that degenerate modes are merged.
- **H7 label.** The match threshold is |log₁₀(f_pred/f_obs)| < 0.05, a factor of 1.122 (−10.9% to +12.2%), not "5%". Each match now shows its actual frequency error. Two of the four "matches" are about 10% off. p = 0.183 is unchanged.
- **Thermal check (Engine 10).** It compared kT/2·f for one mode with E·f·fraction, so it always passed. It now reports E_conf = 2.3 kT and the Boltzmann weight (9.7%), and calls sufficiency **undetermined**: that needs an attempt rate and a barrier the model does not have.
- **Options with a meaningful zero.** pitchAngle = 0, activeFraction = 0, signalAmplitude = 0, perturbRange = 0 and matchThreshold = 0 were silently replaced by defaults through `||`.
- **Engine 8.** Its H2 and H6 sensitivity sweeps used copies of the verdict rules and mismatched baselines (H6 baseline at 16 noise levels, perturbed runs at 12). They now call the shared rules with matching settings.
- **Engine 4 clustering.** Exactly degenerate modes are merged before clustering, so a ±n pair counts as one resonance.

## Not changed, and why

- **H5** peaks at 4°, not 12°, and the docs already said so. It stays inconclusive and fragile (55%).
- **Engine 9's "regular lattice"** is a half-circle phase sweep. It is an arbitrary choice, flagged here but not a math error.
- **Engine 1's coupling** is asymmetric (forward 100× back). It is a stated modelling choice. The audit's "Theorem 1.1" assumes symmetric coupling, so it does not describe this engine.
